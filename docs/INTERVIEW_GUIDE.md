# 현업 인터뷰 진행 가이드 · 체크리스트

연주(연속주조) 부문 슬래브 물류 **최적화/제약 정의**를 위한 현업 인터뷰 진행서입니다.
이 가이드로 인터뷰를 진행하고, 수집한 답변을 [OPTIMIZATION_SPEC.md](OPTIMIZATION_SPEC.md)에
채워 넣으면 이후 D2(CP-SAT 최적화) 착수 자료가 완성됩니다.

- 목적: **목적함수·결정변수·제약·데이터·솔버**를 현업 언어로 확정
- 대상(현업): 연주 조업/스케줄 담당, (선택) 품질·설비·IT
- 준비물: 이 가이드, `OPTIMIZATION_SPEC.md`(빈 양식), `DATA_REQUEST.md`, 데모 앱(스크린샷/라이브)
- 소요: 60~90분 권장

---

## 1. 진행 순서 (아젠다)

| 시간 | 단계 | 내용 |
|------|------|------|
| 5분 | 배경·목표 | 왜 하는지, 오늘 확정할 것(제약·목적) 공유 |
| 10분 | 데모 시연 | 가시화→진단→개선→가이던스 흐름, "샘플 기준 결과" 제시 |
| 10분 | 목적 확정 | 무엇을 최소/최대화? (§3.1) |
| 20분 | 제약 확정 | 라우팅·캐스트 시퀀스·폭 전이·시간/온도·납기 (§3.3) |
| 10분 | 데이터 확인 | 어떤 로그가 어떤 입도로 존재하는지 (§3.4, DATA_REQUEST) |
| 10분 | 솔버·KPI | 해법 방향·계산시간·검증 지표 (§3.6) |
| 5분 | 마무리 | 다음 단계·담당·일정 |

## 2. 데모 시연 워크스루

데모(Streamlit 앱)를 보여주며 "이게 실제로 맞는지" 확인 질문을 던집니다.

1. **📥 과거 데이터** — "이 형식(이벤트 로그)의 데이터를 뽑을 수 있나요?" (→ DATA_REQUEST)
2. **🔎 원인 분석** — "샘플에선 **몰드가 병목**, 원인은 **강종 전환 셋업**으로 나옵니다.
   실제와 일치하나요? 진짜 병목은 어디인가요?"
3. **📈 개선 what-if** — "같은 강종을 묶으면 개선되는데, 실제로 그렇게 묶을 수 있나요?
   못 묶게 하는 제약(납기·폭·턴디시 수명)은 무엇인가요?"
4. **🧭 라우팅 가이던스** — "신규 슬래브가 오면 이렇게 추천합니다. 현업 판단 기준과 다른 점은?"

> 데모의 수치·규칙은 **가정(예시)** 임을 분명히 하고, 현업의 실제 규칙으로 교정받는 것이 목표.

## 3. 질문 체크리스트

`〔 〕`에 답을 적고, 인터뷰 후 `OPTIMIZATION_SPEC.md`로 옮깁니다.

### 3.1 목적 (무엇을 최소/최대화?)
- [ ] 가장 중요한 목표 1~2개는? (납기 지연 / makespan / 처리량 / 전이비용 / 재공 / 가동률)
  → 〔 〕
- [ ] 목표가 여러 개면 **우선순위 또는 가중치**는? → 〔 〕
- [ ] 현재 스케줄을 **누가·어떻게·무엇을 보고** 결정하나요? → 〔 〕

### 3.2 결정 변수 (무엇을 정하나?)
- [ ] 순서(시퀀싱) / cast 구성 / 설비 배정 / 시작시각 중 실제로 "정하는" 것은? → 〔 〕
- [ ] 한 번에 계획하는 단위·기간(horizon)은? (교대/일/주) → 〔 〕

### 3.3 제약 (핵심)
**라우팅·설비**
- [ ] 강종별 필수 경로가 데모(SUS→LF, API→RH, SS→직행)와 맞나요? 예외는? → 〔 〕
- [ ] 설비 동시 처리 대수: LF〔 〕 RH〔 〕 연주기〔 〕 턴디시〔 〕
- [ ] 설비별 처리시간(분)? → 〔 〕

**연주 시퀀스(캐스트)**
- [ ] 턴디시 1개당 최대 연속 heat 수? → 〔 〕
- [ ] 캐스트 내 강종 그룹핑 규칙(같은/유사 강종만)? → 〔 〕
- [ ] **폭 전이 제한**: 연속 슬래브 폭 변화 허용 범위(감소만? 증가 상한?) → 〔 〕
- [ ] 두께/폭 조합 제약? → 〔 〕

**시간·온도**
- [ ] 출강 후 주조까지 최대 허용 시간(분)? → 〔 〕
- [ ] 온도 하/상한, 재가열 조건? → 〔 〕

**수요·납기**

### 3.4 데이터
